Google sign-in that works for everyone, with safe logging and admin control.

CoreOptional for users

Google sign-in

  • Use Google's official sign-in with minimal scopes: name, email and profile photo.
  • Ask for sign-in only when a feature needs it.
  • Keep requests low and steady so Google does not flag the site as suspicious.

Works everywhere

  • Test on Brave, which blocks third-party cookies and some sign-in pop-ups.
  • Add a redirect-based fallback when the pop-up or One Tap prompt fails.
  • Keep the sign-in page light for low-end phones and slow networks.

Persistent session

  • Issue the site's own long-lived login, separate from Google's session.
  • Login survives page refreshes and browser cache clearing.
  • Only an explicit sign-out ends the session.

Admin: logs and blocking

  • Log each sign-in with email, name, time and device type.
  • Log key activity: questions solved, tests taken and bookmarks.
  • Admin view shows the full activity of any user.
  • Block specific emails from signing in or saving data.

Unlocks: every account feature in phases 2 to 4.

Give signed-in users a notebook and a profile. Protect the sources box from scraping.

Needs phase 1Optional for users

Sources box gate

  • Visitors without an account see the sources box freely for 10 views.
  • From the 11th view, only the sources box locks and asks for sign-in.
  • Questions, answers and explanations keep working without sign-in.
  • The prompt says the site stays 100% free and sign-in only helps prevent scraping.

Bookmarks

  • Add a bookmark icon at the top right of every question card.
  • One tap saves or removes the question.
  • Signed-out visitors get a short, friendly sign-in prompt.

Metis notebook

  • Sits in the sidebar and appears only after sign-in.
  • Starts with a Bookmarks tab.
  • A second tab arrives with test mode in phase 3.

Profile

  • Profile section in the sidebar for signed-in users.
  • Stores the full name from the user's Google account.
  • That name appears on leaderboards in phase 4.

Unlocks: a saved identity and a place to keep mistakes.

Timed practice in the All India exam format, mistakes saved to the notebook, and printable question papers.

Needs phases 1 and 2Optional for users
100 questions120 minutes7,200 s ÷ 100 = 72 s per question

Exam format

  • All India test of 100 questions in 120 minutes.
  • Each question gets a 72-second time allotment.
  • The test submits automatically when the timer ends.

Navigator

  • Grid layout showing question numbers.
  • Move back and forth freely between questions.
  • Skip a question for now and return to it later.
  • Grid shows answered, skipped and unvisited questions.

Choose what to attempt

  • Year-wise tests.
  • Subject-wise tests.
  • Topic-wise tests.
  • Exam-wise tests.
  • Custom selection with bulk select: pick a whole filter at once, then deselect individual questions.

Print question papers

  • Print by subject, topic, year, exam or a custom selection.
  • The page follows the official UPSC question paper format: header, instructions, numbered questions and options.
  • A faint pyq-project.in watermark sits behind the text so it never distracts from reading.
  • Custom prints reuse the same bulk selection as custom tests.

Mistakes in the notebook

  • Metis notebook now has two tabs: Bookmarks and Test wrong answers.
  • Wrong answers save automatically after each test.
  • Each saved item links back to its explanation.

Unlocks: scored attempts that phase 4 can rank.

Show progress and friendly competition so users come back daily.

Heatmap and streak

Question leaderboard

Test mode leaderboards

  • Subject-wise leaderboard.
  • Topic-wise leaderboard.
  • Year-wise leaderboard.
  • Year plus UPSC-selected leaderboard.
  • The goal is to motivate and hook users, so the final shape stays flexible.

Settle these before the related phase starts. Each one changes what you build.

Open decisions

  • Timer: one overall 120-minute clock, a hard 72-second limit per question, or both.
  • Sources view count: browser storage is easy to reset, so a server-side count per device or IP is stronger.
  • Leaderboards show full Google names, so consider an optional display name for privacy.
  • Clearing cookies can still end a login, unless a backup token is kept in local storage.
  • Add a short privacy note covering what is logged and why.
  • Printed papers: questions only, or an optional answer key and explanations at the end.

Fix the scroll jump on iOS first. It affects every long question on the live site.

BugLive site

The bug

  • On iOS, a tall question can sit with its top half off screen.
  • Tapping an option in that state makes the page jump.
  • The jump breaks the reading flow.

Things to check

  • Focus moving to the tapped option can scroll the page.
  • Re-rendering the question card can reset the scroll position.
  • Content added above the viewport, such as the explanation, can shift the layout.
  • iOS Safari handles scroll anchoring differently from other browsers.

Done when

  • Tapping any option leaves the scroll position unchanged.
  • Tested on iOS Safari, iOS Brave and a low-end Android phone.
